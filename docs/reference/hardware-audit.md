# 硬件核对记录与原型接线建议

更新日期：2026-09-03

## 结论先行

现有资料足以冻结 MVP 接线：电子秤必须接 `EXT`，一块 STC 同时负责称重与计费，板载 RS-485 直接连接 EKT043_EDU。`EXT` 的 P1.0/P1.1 在称重模式下作为两线采集接口，而 UART2 映射到 P4.6/P4.7 驱动板载 MAX485；这里不是把 EXT 当成第二个串口。

## 关键冲突

1. `EXT/UART2` 使用 P1.0/P1.1；`RS-485/UART2` 使用 P4.6/P4.7，并由 P3.7 控制收发方向。它们是同一个 UART2，不是两路 UART。
2. 称重模式把 EXT 当作 HX710/HX711 两线接口，不能同时再把同一 EXT 初始化为超声波、PWM 或 TTL 串口。
3. UART1 的 P3.0/P3.1 已连接板载 CH340。外接另一个串口发送端时可能出现两个器件同时驱动 RX 的电气冲突。
4. 两块学习板均确认使用 `IAP15F2K61S2`，与原理图一致；课程 BSP 使用 `STC15F2K60S2.H`。STC-ISP 下载时必须选择实物型号，Keil 头文件能否沿用需通过最小工程验证，不能仅因同系列而默认完全兼容。

## 冻结的原型硬件路线

主控板连接如下：

| 功能 | 连接 |
|---|---|
| 电子秤供电 | EXT-1 5V、EXT-4 GND；先核对秤模块允许电压和插头方向 |
| 电子秤数据 | `EXTInit(enumEXTWeight)` + `GetWeight()`；按接口方向推定 DOUT→P1.0、SCK→P1.1 |
| 显示通信 | STC CON2-2(A)→DWIN 39(485A)，CON2-1(B)→DWIN 40(485B)，另接共地 |
| DWIN 处理 | T5L OS 使用 UART4/RS-485 解析帧并更新 DGUS VP |

第二块 STC 不进入 MVP 主链路，保留为后期测高/RFID 扩展或备件。完整断电接线和上电顺序见 `final-wiring.md`。

## 开始完整联调前仍需确认的 2 项

1. 电子秤无明显丝印：拍摄模块/插头正反面或用万用表确认 5V、GND 与信号线顺序，禁止仅按线色接电；
2. 把 DWIN 工程 UART4/RS-485 设为 9600、8N1，并用固定测试帧验证 T5L OS 与 STC 的收发。

## 电源与接线安全

- 所有 TTL/RS-485 通信设备必须共地；A/B 线不要只凭颜色判断；
- DWIN 可使用 12V 独立稳压电源，绝不能把 12V 接入 STC 的 5V/3.3V 引脚；
- 未确认 DWIN 端口电平前，不要直连；
- 第一阶段一次只接一个新模块，先空载、再小砝码、最后全量程测试。
