# STC 源码逐文件、逐变量详解

本文对应仓库内正式 Keil 工程：`firmware/stc`。

Keil 实际参与编译或链接的内容只有：

| 类型 | 文件 | 作用 |
|---|---|---|
| C 源码 | `source/main.c` | 初始化、事件调度、命令接收、状态生成和串口发送 |
| C 源码 | `source/weight_service.c` | 原始称重值转换、清零、去皮、标定、平均滤波和稳定判断 |
| C 源码 | `source/billing.c` | 地区费率选择、参数检查和计费 |
| C 源码 | `source/parcel_protocol.c` | 26 字节协议帧、CRC8、大端整数转换 |
| 汇编启动文件 | `STARTUP.A51` | 复位入口、内部 RAM 和堆栈初始化，最后转入 C 程序 |
| 预编译库 | `lib/STCBSP_V3.6b.LIB` | 课程 BSP：定时、UART2、按键、电子秤、EEPROM、DS1302 等驱动 |

`inc` 中的头文件本身不单独生成程序，但它们声明类型、宏和外部接口，决定各 `.c` 文件怎样解释数据，因此也必须一起理解。

---

## 一、先理解 C51 中的特殊关键字

### `code`

`code` 表示对象放在 8051 的程序存储器中，通常就是 Flash/ROM，只读且不占宝贵的内部 RAM。

```c
code unsigned long SysClock = 11059200UL;
```

`SysClock` 是给 BSP 使用的系统时钟常量，值为 11.0592 MHz。

`billing.c` 中的费率表也使用 `code`，因为运行时只读取、不修改。

### `xdata`

`xdata` 表示对象位于 8051 的外部数据地址空间。STC15 芯片通常把片内扩展 RAM 映射到这个空间。协议帧、称重结构体等较大对象放在这里，可节省很小的内部 `data` RAM。

### `volatile`

`volatile` 表示变量可能在当前代码看不到的位置发生变化，编译器每次都必须真正访问内存，不能把值长期缓存到寄存器。

本工程的 `g_tick10_event` 和 `g_rx_event` 由 BSP 回调置位、由主循环读取和清零，所以声明为 `volatile`。

### `static`

文件作用域函数前的 `static` 表示函数只供本 `.c` 文件使用，不向其他模块导出。例如 `process_rx()` 只属于 `main.c`。

### 数字后缀

| 后缀 | 含义 | 例子 |
|---|---|---|
| `U` | 无符号整数 | `1U` |
| `L` | 长整数 | `-5L` |
| `UL` | 无符号长整数 | `1000UL` |

这些后缀在 C51 中很重要，因为普通 `int` 通常只有 16 位，而 `long` 才是 32 位。

## 二、`inc/project_config.h`：全局编译配置

头部的 `#ifndef / #define / #endif` 是头文件保护，防止同一头文件被重复包含后发生重复定义。

### `LINK_TEST_MODE`

```c
#define LINK_TEST_MODE 0
```

- `0`：正式模式，使用真实称重值、真实稳定状态和真实错误判断。
- `1`：链路测试模式，不依赖秤，固定发送 `1234 g`，便于只检查 STC→DWIN 的 RS-485、协议解析和界面显示。

它是编译期开关。`#if LINK_TEST_MODE` 未被选中的代码不会进入最终固件，并不是运行中可切换的变量。

测试模式下状态标志固定为 `0x001F`，即 bit0～bit4 全为 1。

### `WEIGHT_RAW_COUNT_MODE`

```c
#define WEIGHT_RAW_COUNT_MODE 1
```

- `1`：把 `abs(GetWeight() - zero_raw)` 近似直接当成克数；不用砝码标定，但“1 计数是否等于 1 克”取决于硬件。
- `0`：使用零点和已知砝码形成的两点标定比例，转换成克。

当前为 `1`，因此上电后 `weight_use_raw_counts()` 会令 `span_raw=1`、`span_mass_g=1`，相当于比例系数为 1。

### 时间和通信配置

| 宏 | 当前值 | 实际含义 |
|---|---:|---|
| `RS485_BAUD` | 9600 | UART2 的 RS-485 波特率 9600 bit/s |
| `STATUS_PERIOD_10MS` | 50 | 每 50×10 ms，即 500 ms 请求发送一次状态帧 |
| `WEIGHT_SAMPLE_PERIOD_10MS` | 2 | 每 2×10 ms，即 20 ms采一次重量 |

宏名中的 `_10MS` 表示数值单位不是毫秒，而是“多少个 10 ms 节拍”。

### `DEFAULT_*` 四个宏

```c
DEFAULT_FIRST_WEIGHT_G
DEFAULT_FIRST_PRICE_CENT
DEFAULT_STEP_WEIGHT_G
DEFAULT_STEP_PRICE_CENT
```

设计上分别代表默认首重、首重价、续重单位、续重价。当前版本中它们没有被任何 `.c` 文件引用；真实费率来自 `billing.c` 的 `g_region_tariffs`。因此修改这四个宏不会改变当前计费结果。

### 稳定判断配置

| 宏 | 值 | 含义 |
|---|---:|---|
| `STABLE_WINDOW_SIZE` | 8 | 保存最近 8 次净重样本 |
| `STABLE_RANGE_G` | 5 | 一个窗口内最大值与最小值之差不得超过 5 g |
| `STABLE_REQUIRED_WINDOWS` | 5 | 连续 5 次窗口检查合格才认为稳定 |
| `MAX_WEIGHT_G` | 30000 | 最大允许重量 30000 g，即 30 kg |

这 5 个“窗口”是相邻采样形成的重叠窗口，并非 5 组完全独立的 8 个样本。

## 三、`inc/parcel_protocol.h`：协议类型、常量和数据结构

### 跨编译器整数类型

在 Keil C51 下：

| 类型 | 底层类型 | 预期位宽 | 用途 |
|---|---|---:|---|
| `pp_u8` | `unsigned char` | 8 位 | 字节、命令、序号、布尔标志 |
| `pp_u16` | `unsigned int` | 16 位 | 两字节状态标志 |
| `pp_u32` | `unsigned long` | 32 位 | 重量字段、价格、参数 |
| `pp_s32` | `signed long` | 32 位有符号 | 允许出现负值的重量和原始差值 |

非 C51 环境改用 `<stdint.h>`，使计费单元测试也能在 PC 上编译。

### 帧常量

```text
下标 0  1   2    3    4    5    6    7……24      25
内容 AA 55  DST  SRC  CMD  SEQ  LEN  DATA[18]   CRC8
```

| 宏 | 值 | 含义 |
|---|---:|---|
| `PP_HEADER_0` | `0xAA` | 第一个帧头字节 |
| `PP_HEADER_1` | `0x55` | 第二个帧头字节 |
| `PP_DATA_SIZE` | 18 | 固定数据区长度 |
| `PP_FRAME_SIZE` | 26 | 整帧固定长度 |

`LEN` 只表示 `DATA[18]` 中前多少字节有效；没有使用的位置仍补 0，并且仍参与 CRC。

### 地址

| 地址 | 含义 |
|---:|---|
| `0x01` | STC 主控 |
| `0x02` | DWIN 屏 |
| `0xFF` | 广播地址 |

STC 接收时允许目的地址为 `0x01` 或 `0xFF`，但之后要求源地址必须为 `0x02`。

### 命令码

| 命令 | 方向 | 含义 | 当前实现 |
|---:|---|---|---|
| `0x01 STATUS` | STC→DWIN | 重量、价格、状态和皮重 | 已使用 |
| `0x02 PARAMS` | STC→DWIN | 当前计费参数和地区 | 已使用 |
| `0x03 RTC` | STC→DWIN | DS1302 时间 | 已使用 |
| `0x10 ZERO` | DWIN→STC | 清零 | 已使用 |
| `0x11 TARE` | DWIN→STC | 去皮 | 已使用 |
| `0x12 REBILL` | DWIN→STC | 要求立即刷新计费状态 | 已使用 |
| `0x13 SET_PRICE` | DWIN→STC | 自定义费率 | 只保留定义；固定三档版本会当未知命令拒绝 |
| `0x14 CALIBRATE` | DWIN→STC | 用已知质量完成跨度标定 | 已使用 |
| `0x15 SET_REGION` | DWIN→STC | 选择地区 1/2/3 | 已使用 |
| `0x20 HEARTBEAT` | DWIN→STC | 心跳探测 | 只回复成功，不改变状态 |
| `0x7E ACK` | STC→DWIN | 命令成功 | 已使用 |
| `0x7F NACK` | STC→DWIN | 命令失败 | 已使用 |

### `pp_packet_t`

这是“解析后的逻辑数据包”：

| 成员 | 含义 |
|---|---|
| `dst` | 目的地址 |
| `src` | 源地址 |
| `cmd` | 命令码 |
| `seq` | 序号，用于请求匹配和防重复执行 |
| `len` | 有效载荷长度 |
| `payload[18]` | 数据区副本 |

它不保存 `AA 55` 和 CRC，因为这两部分只用于传输边界及完整性检查，不属于业务内容。

## 四、`source/parcel_protocol.c`：帧编码和整数编解码

### `pp_crc8(bytes, len)`

局部变量：

| 变量 | 作用 |
|---|---|
| `crc` | 当前 8 位 CRC 余数，初值为 0 |
| `i` | 当前正在处理第几个字节 |
| `bit_index` | 当前字节内部已经处理了几位 |

算法是 CRC-8/ATM，多项式 `0x07`、初值 `0`。每个输入字节先与 `crc` 异或，然后循环 8 次：若最高位 `0x80` 为 1，就左移并异或多项式，否则只左移。

发送端与接收端都调用同一函数，因此参数不会产生偏差。帧中计算范围是 `frame[2]` 到 `frame[24]`，共 23 字节：5 个控制字段加完整 18 字节数据区。帧头和 CRC 自身不参与。

### `pp_build(dst, src, cmd, seq, payload, len, frame)`

参数与局部变量：

| 名称 | 作用 |
|---|---|
| `dst/src/cmd/seq` | 写入帧下标 2～5 |
| `payload` | 业务数据首地址，可为空 |
| `len` | 有效业务数据长度，必须不超过 18 |
| `frame` | 调用者提供的 26 字节输出缓冲区 |
| `i` | 填充 18 字节数据区的循环下标 |

执行顺序：检查输出指针和长度；写入帧头及字段；把有效载荷复制到 `frame[7...]`；其余数据区补 0；计算 `frame[25]`；成功返回 1。

当前实际行为：如果 `payload==0` 但 `len>0`，函数不会报错，而会把数据区补 0、仍把 `LEN` 写成非零。调用方目前没有这样使用，但接口本身并未禁止。

### `pp_put_u16/pp_put_u32`

把整数按大端序写入字节数组，即高字节在前。例如 `0x12345678` 写成 `12 34 56 78`。显式转换为 `pp_u8` 的作用是只保留移位后的低 8 位。

### `pp_get_u16/pp_get_u32`

执行相反操作，把大端字节拼回整数。移位前先转换成目标宽度，尤其能避免 C51 的 16 位 `int` 在左移 24 位时丢失数据。

状态帧中的重量虽然逻辑上是 `pp_s32`，发送时会转换为 `pp_u32`。这不会改变 32 位补码的比特图案；DWIN 再按有符号 32 位解释即可恢复负数。

## 五、`inc/billing.h` 与 `source/billing.c`：计费模块

### `billing_params_t`

| 成员 | 单位 | 含义 |
|---|---|---|
| `first_weight_g` | g | 首重包含的重量 |
| `first_price_cent` | 分 | 首重价格 |
| `step_weight_g` | g | 每一个续重计费单位 |
| `step_price_cent` | 分 | 每个续重单位价格 |

全部使用整数克和整数分，避免 8051 使用浮点数带来的体积、速度和舍入问题。

### 地区宏与 `region_tariff_t`

地区编号为 1 省内、2 普通省外、3 偏远，默认 1，共 3 项。`region_tariff_t` 把一个 `region_id` 和一组 `billing_params_t` 绑定。

### `g_region_tariffs`

这是只读费率表：

| 地区 | 首重 | 首重价 | 续重单位 | 续重价 |
|---|---:|---:|---:|---:|
| 省内 | 1000 g | 800 分 | 1000 g | 200 分 |
| 普通省外 | 1000 g | 1200 分 | 1000 g | 400 分 |
| 偏远 | 1000 g | 1800 分 | 1000 g | 800 分 |

`#ifdef __C51__` 下使用 `code`，在 PC 单元测试中使用标准 `const`。内容相同，只是存储方式适配不同编译器。

### `billing_region_params(region_id, params)`

- `region_id`：想查找的地区编号。
- `params`：输出地址，找到后把对应四项费率复制进去。
- `i`：遍历三项费率表的下标。
- 返回 1：找到且已复制；返回 0：输出指针为空或地区不存在。

这里逐字段复制，而不是直接结构体赋值，兼容 C51 的存储空间差异：源表在 `code`，目标通常在 `xdata`。

### `billing_params_valid(params)`

检查：指针非空；两个重量单位不能为 0；重量项不能超过 100000 g；价格项不能超过 1000000 分。价格允许为 0，因此可以表达免费首重或免费续重。

这些上限首先是输入防御，并不等于本项目秤的量程；真正称重上限是 `MAX_WEIGHT_G=30000`。

### `billing_calculate(weight_g, params, price_cent)`

局部变量：

| 变量 | 含义 |
|---|---|
| `weight` | 已确认大于 0 后，将有符号重量转换成无符号数 |
| `excess` | 超出首重的克数 |
| `steps` | 要收取的续重单位数量 |

公式：

```text
weight <= 0                         → 0 分
0 < weight <= first_weight         → 首重价
weight > first_weight              → 首重价 + 向上取整(超出重量/续重单位)×续重价
```

`excess / step_weight_g` 先求完整单位；若余数不为 0，再把 `steps` 加 1，实现向上取整。

第 73～75 行在乘法前检查 32 位无符号溢出。若结果会超过 `0xFFFFFFFF`，返回 0，不写出错误价格。

返回值表示“计算是否成功”，价格本身通过 `*price_cent` 输出，因此正常的 0 元和失败返回 0 是两件不同的事。

## 六、`inc/weight_service.h` 与 `source/weight_service.c`：称重模块

### `weight_service_t` 每个成员

| 成员 | 含义 | 谁修改 |
|---|---|---|
| `zero_raw` | 空载零点的 ADC 原始值 | 初始化、清零 |
| `span_raw` | 已知砝码原始值与零点的差 | 标定或原始计数模式 |
| `span_mass_g` | `span_raw` 所对应的已知质量 | 标定或原始计数模式 |
| `tare_g` | 已扣除的皮重，单位 g | 去皮、清零 |
| `samples[8]` | 最近净重样本环形缓冲区 | 每次采样 |
| `filtered_g` | 当前样本窗口的算术平均净重 | 每次采样 |
| `sample_count` | 当前有效样本数，最大 8 | 初始化、模式切换、清零、标定、去皮、采样 |
| `sample_index` | 下一次写入 `samples[]` 的位置 | 每次采样 |
| `stable_windows` | 连续合格窗口次数，最大 5 | 每次采样、清零、去皮 |
| `calibrated` | 1 表示当前已有可用换算比例 | 初始化、标定、原始计数模式 |
| `stable` | 1 表示重量已满足稳定条件 | 每次采样、清零、去皮 |
| `raw_count_mode` | 1 表示对原始差值取绝对值并按 1:1 使用 | 原始计数模式或正式标定 |

这些所谓“标志位”实际都是整个 `pp_u8` 变量，只约定使用 0/1，并不是挤在同一个字节中的 C 位域。

### `raw_to_g(service, raw)`

这是文件内部函数。

- `delta = raw - zero_raw`：本次原始值相对空载零点的变化。
- 原始计数模式下若 `delta<0`，取绝对值，兼容不同传感器接线导致的方向相反。
- `value = delta × span_mass_g / span_raw`：按两点标定做比例换算。
- 未标定或 `span_raw==0` 时返回 0，避免无比例或除零。

正常标定允许 `span_raw` 为负数；如果加砝码后 ADC 方向向下，`delta` 与 `span_raw` 同为负，最终克数仍为正。

### `weight_init(service, initial_raw)`

将上电时的原始值当作初始零点；清空跨度、皮重、滤波值、样本计数、稳定计数和所有样本；把三个模式/状态标志设为 0。

调用它时要求秤已初始化并最好处于空载，否则上电物体会被当成零点的一部分。

### `weight_use_raw_counts(service)`

设置 `span_raw=1`、`span_mass_g=1`，令比例公式退化为“原始差值就是克数”；同时把 `calibrated` 和 `raw_count_mode` 置 1，并要求重新积累样本与稳定窗口。

这里的“calibrated=1”表示换算通道可以工作，不表示完成了真实砝码标定。

### `weight_zero(service, raw)`

将当前 ADC 原始值保存为新 `zero_raw`，把皮重清零，并清除有效样本数和稳定状态。它保留已有跨度比例，所以正式标定后重新清零不需要再次标定。

“清零”和“去皮”的区别：清零改变 ADC 坐标原点并取消皮重；去皮不改 ADC 零点，只在克数层累计扣除量。

### `weight_calibrate(service, raw, known_mass_g)`

- `known_mass_g` 必须在 1～30000 g。
- `span = raw - zero_raw` 是砝码造成的原始跨度。
- `-10 < span < 10` 被认为变化太小，拒绝标定，防止噪声被放大成巨大比例。
- 成功后保存跨度和砝码质量，`calibrated=1`，并退出原始计数模式。

返回 1 表示成功，0 表示砝码参数或跨度无效。

当前实现只清 `sample_count`，没有同步清 `stable_windows` 和 `stable`；下一次采样会继续更新它们。这是当前源码的真实细节，不应误解为标定成功后立即保证稳定状态已清空。

### `weight_tare(service)`

```c
service->tare_g += service->filtered_g;
```

把当前已经显示的净重继续累计到皮重里。因此第一次放容器去皮后，容器净重变成约 0；再次去皮也能基于当前净重继续调整。随后重新积累样本并清除稳定标志。

### `weight_push_raw(service, raw)`

局部变量：

| 变量 | 含义 |
|---|---|
| `gross` | 当前原始值换算并扣皮后的单次净重；名字虽叫 gross，实际已减去 tare |
| `sum` | 有效样本总和，用于算平均 |
| `min_value` | 当前窗口最小值 |
| `max_value` | 当前窗口最大值 |
| `i` | 遍历样本下标 |

流程：

1. 未标定时强制 `filtered_g=0`、`stable=0` 并返回。
2. 换算克数并减去 `tare_g`。
3. `-4～-1 g` 的微小负漂移归零；`-5 g` 及以下仍保留，便于发现明显反向偏移。
4. 写入环形缓冲区，移动 `sample_index`，把 `sample_count` 增长到最多 8。
5. 对当前样本求平均、最小值和最大值。
6. 满 8 个样本且极差不超过 5 g 时，连续合格计数加 1；否则清零。
7. 连续合格数达到 5 后令 `stable=1`。

20 ms 采样下，从空缓冲开始，最早第 8 个样本得到第一个合格窗口，第 12 个样本得到第 5 个合格窗口，约 240 ms 可进入稳定状态。

当前环形缓冲有一个短时细节：清零、去皮或标定把 `sample_count` 清零，却没有把 `sample_index` 归零；重新收集未满 8 个样本时，代码仍遍历 `samples[0..sample_count-1]`。若清零发生时写指针不在 0，最初几次平均可能混入旧数组位置，等 8 个位置重新写满后自动消失。这不影响长期稳态，但会影响操作后的短暂过渡读数。

## 七、`source/main.c`：应用主控

### 1. 两组枚举

#### `app_state`

| 值 | 名称 | 含义 | 当前是否产生 |
|---:|---|---|---|
| 0 | `APP_IDLE` | 重量小于等于 0，空闲 | 是 |
| 1 | `APP_WEIGHING` | 有重量但尚未稳定 | 是 |
| 2 | `APP_STABLE` | 稳定但未计费 | 当前未赋值，是预留状态 |
| 3 | `APP_BILLING` | 已稳定并完成计费 | 是 |
| 4 | `APP_ERROR` | 存在错误 | 是 |

#### `app_error`

| 值 | 名称 | 含义 | 当前是否设置 |
|---:|---|---|---|
| 0 | `ERR_NONE` | 无错误 | 是 |
| 1 | `ERR_SENSOR` | 传感器错误 | 预留，当前没有检测代码 |
| 2 | `ERR_OVER_RANGE` | 超量程或明显负偏移 | 是 |
| 3 | `ERR_CALIBRATION` | 未标定或标定命令失败 | 是 |
| 4 | `ERR_PARAMS` | 地区/计费参数无效 | 是 |
| 5 | `ERR_SAVE` | EEPROM 保存失败 | 预留，当前写后不校验 |
| 6 | `ERR_UNKNOWN_CMD` | 不认识的命令 | 是 |
| 7 | `ERR_STATE` | 当前状态不允许操作 | 预留 |

### 2. EEPROM 地区编码

`NVM_REGION_ADDR=0xE0` 是 M24C02 存储单元地址。`NVM_REGION_TAG=0xA0` 是有效标记。实际写入值为 `0xA0 | region_id`，即地区 1/2/3 分别保存为 `0xA1/0xA2/0xA3`。

启动时先检查高四位是否为 `0xA`，再取低四位作为地区；随后仍通过 `billing_region_params()` 二次验证，非法编号会回退到默认省内。

### 3. 所有全局变量

| 变量 | 作用与生命周期 |
|---|---|
| `SysClock` | BSP 使用的 11.0592 MHz 时钟常量，必须与下载/硬件时钟一致 |
| `g_rx_frame[26]` | UART2 BSP 把一整帧接收到这里 |
| `g_tx_frame[26]` | 所有发送函数共用的组帧缓冲区 |
| `g_frame_header[2]` | 保存 `AA 55`，传给 BSP 作为接收匹配帧头 |
| `g_weight` | 唯一的称重服务状态，包含零点、皮重、滤波和稳定信息 |
| `g_billing` | 当前地区对应的四项费率参数 |
| `g_tick10_event` | 10 ms 事件待处理标志；回调置 1，主循环处理后清 0 |
| `g_rx_event` | 完整接收帧待处理标志；回调置 1，主循环处理后清 0 |
| `g_tick_divider` | 称重采样分频计数；到 2 触发一次 20 ms 采样 |
| `g_status_ticks` | 状态周期计数；到 50 请求一次 500 ms 状态发送 |
| `g_status_pending` | 状态帧待发标志；UART 忙时保留，发送成功后清零 |
| `g_params_pending` | 参数帧待发标志；上电和地区变化时置位 |
| `g_rtc_ticks` | RTC 周期计数；到 100 请求一次 1 s 时间发送 |
| `g_rtc_pending` | RTC 帧待发标志 |
| `g_tx_seq` | STC 主动发送帧的 8 位递增序号，溢出后自然回到 0 |
| `g_latest_raw` | 最近一次读取的电子秤 ADC 原始值，供采样、清零和标定使用 |
| `g_region_id` | 当前地区编号 1/2/3 |
| `g_last_rx_valid` | 是否已有一条可用于去重的历史命令 |
| `g_last_rx_cmd` | 上一次实际执行的命令码 |
| `g_last_rx_seq` | 上一次实际执行的命令序号 |
| `g_last_rx_result` | 上一次命令结果；重复帧直接复用它回复，不重复执行动作 |
| `g_rx_diag_stage` | 接收链路诊断阶段/错误码，装入状态帧原“高度”字段的高字节 |

`g_tick10_event` 和 `g_rx_event` 是布尔事件，不是计数器。如果主循环阻塞很久，多个事件都只表现为 1；本程序依赖 `MySTC_OS()` 和各任务快速返回来避免丢失节拍或覆盖接收帧。

### 4. `on_10ms()` 与 `on_uart2_rx()`

两者都是尽量短的回调：只置事件标志。串口回调额外增加帧计数，并令诊断阶段为 1，表示 BSP 已经按 `AA 55` 帧头收齐 26 字节。

回调不直接做 CRC、计费或发送，是为了不长时间占用 BSP/中断上下文。

### 5. `send_frame()`

先检查 UART2 发送器是否空闲，再调用 `pp_build()` 生成一帧；目的固定为 DWIN，源固定为 STC；最后让 BSP 异步发送完整 26 字节。

返回 1 表示 BSP 接受发送任务，不表示对端已经收到。

### 6. `send_reply()`

两字节载荷为“原请求命令码 + 结果码”。结果为 0 发送 ACK，否则发送 NACK。回复沿用请求的 `SEQ`，使 DWIN 能把回复和触摸命令对应起来。

### 7. `apply_command()`

局部 `known_mass` 只在标定命令中使用，接收四字节大端已知质量。

各分支：

- `ZERO`：以 `g_latest_raw` 为新零点，立即请求状态帧。
- `TARE`：非链路测试模式下必须已有可用标定比例；去皮后请求状态帧。
- `REBILL`：不单独保存价格，因为价格由当前重量实时生成；这里只要求尽快再发状态。
- `CALIBRATE`：载荷必须恰好 4 字节；解析已知克数并用当前原始值标定。
- `SET_REGION`：载荷必须恰好 1 字节且地区存在；切换费率、写 EEPROM，并请求参数帧和状态帧。
- `HEARTBEAT`：直接成功，不改业务状态。
- 其他命令：返回未知命令，包括预留的 `SET_PRICE`。

### 8. `inspect_rx_frame()`

按顺序检查并返回诊断码：

| 返回值 | 含义 |
|---:|---|
| `0xD1` | 帧头不是 `AA 55` |
| `0xD2` | `LEN>18` |
| `0xD3` | 目的地址既不是 STC 也不是广播 |
| `0xD4` | CRC 不匹配 |
| `0` | 基础帧检查通过 |

检查顺序意味着一帧同时有多个问题时，只报告最先遇到的一项。

### 9. `is_safe_zero_frame()`

这是专用于联调兼容的 CRC 例外路径。仅当帧头、STC 目的地址、DWIN 源地址、ZERO 命令、`LEN=0` 和 18 个保留数据字节全都正确时，才允许“只有 CRC 错”的清零帧执行。任何其他命令都不能绕过 CRC。

### 10. `process_rx()`

局部变量：`packet` 保存解析结果，`result` 保存命令执行错误码，`frame_error` 保存帧检查码，`i` 复制 18 字节载荷。

流程：

1. 没有接收事件则立即返回；有事件先清标志。
2. 校验当前 `g_rx_frame`。
3. 若只是满足严格条件的 ZERO CRC 错，走兼容清零；其他帧错误只记录诊断，不执行业务命令。
4. 把 `xdata` 接收缓冲逐字段复制到局部 `packet`。源码特意不跨模块调用通用解析器，是为了避开 C51 不同存储空间指针模型的兼容问题。
5. 检查源地址必须是 DWIN；失败记 `0xE2`。
6. 若命令码和序号与上次完全相同，视为 DWIN 重发，只复用旧结果，不再次清零、去皮或写 EEPROM。
7. 新命令才调用 `apply_command()`，并更新去重缓存。
8. 尝试回复 ACK/NACK；成功阶段为 5，UART 忙导致失败记 `0xE3`。
9. 无论命令成功与否，都请求状态帧，让屏幕看到最新诊断和状态。

去重只缓存最近一条命令。源地址已经被限定为 DWIN，因此缓存中不再保存源地址。

### 11. `process_10ms()`

局部 `key_action` 保存本次 K1 事件。

每次消费一个 10 ms 事件时：读取 K1，检测到 `enumKeyPress` 就本地清零；三个周期计数器各加 1；每 20 ms 读一次 `GetWeight()` 并推进称重滤波；每 500 ms 置状态待发；每 1 s 置 RTC 待发。

K1 是屏幕命令之外的后备清零入口。若 K1 有效而屏幕按钮无效，应重点检查 DWIN→STC 反向链路和触摸 VP。

### 12. `build_runtime_status()` 与状态标志

输出参数：

- `weight_g`：当前净重。
- `price_cent`：当前计费结果。
- `state`：应用状态码。
- `flags`：16 位状态位集合。
- `error`：单一错误码。

`flags` 的当前定义：

| 位 | 掩码 | 为 1 的含义 |
|---:|---:|---|
| bit0 | `0x0001` | 重量稳定 |
| bit1 | `0x0002` | 传感器存在；当前代码默认置 1，没有真实故障检测 |
| bit2 | `0x0004` | 重量在允许范围内 |
| bit3 | `0x0008` | 计费参数有效 |
| bit4 | `0x0010` | 链路测试模式 |
| bit5～7 | — | 未使用 |
| bit8～15 | `region_id<<8` | 当前地区编号 |

正式模式先把 bit1、bit2 置 1，即 `0x0006`；参数合法再置 bit3；稳定再置 bit0；超量程时清 bit2；最后把地区号放入高字节。

错误判断存在覆盖优先级：参数错误先写 `ERR_PARAMS`，未标定会覆盖为 `ERR_CALIBRATION`，超量程又会覆盖为 `ERR_OVER_RANGE`。所以同时存在多个问题时，最终只传优先级更后的那个错误码。

状态选择：有错误为 ERROR；重量不大于 0 为 IDLE；正重量但不稳定为 WEIGHING；稳定后为 BILLING 并计算价格。`APP_STABLE` 当前没有单独使用。

### 13. `try_send_status()`

只有“待发标志为 1且 UART 空闲”才工作。18 字节载荷布局：

| DATA 下标 | 长度 | 内容 |
|---:|---:|---|
| 0 | 4 | 有符号重量的 32 位比特图案 |
| 4 | 4 | 价格，单位分 |
| 8 | 1 | 应用状态 |
| 9 | 2 | 状态 flags |
| 11 | 2 | 高字节诊断阶段，低字节接收帧计数；借用了原预留高度字段 |
| 13 | 1 | 错误码 |
| 14 | 4 | 皮重 |

发送成功才清 `g_status_pending`。`g_tx_seq++` 在调用发送函数时已经执行，因此即使极少数情况下发送失败，序号也可能跳过一个值；协议并不要求序号连续无缺口。

### 14. `try_send_params()`

17 字节依次放四个大端 32 位费率和 1 字节地区编号。上电时发送一次；切换地区时再次发送。发送成功才清待发标志。

### 15. `bcd_to_dec()` 与 `try_send_rtc()`

DS1302 使用 BCD，例如 `0x26` 表示十进制 26。转换公式是“高四位×10 + 低四位”。

读取 RTC 后，对月、日、星期、时、分、秒分别先用掩码去掉 DS1302 寄存器中的控制位，再转为普通二进制。7 字节顺序为年、月、日、星期、时、分、秒。发送成功才清 `g_rtc_pending`。

### 16. `app_init()`

1. 读取当前秤原始值并建立称重服务。
2. 编译配置为原始计数模式时启用 1:1 换算。
3. 从 M24C02 读取地区，检查 `0xA` 标签和地区表；无效则使用省内。
4. 清所有事件、周期计数和去重缓存。
5. 把状态、参数和 RTC 待发标志初始置 1，保证上电后尽快同步屏幕。
6. 设置 `g_rx_diag_stage=0xA0`，作为“诊断版固件已启动”的标记。

### 17. `main()`

`initial_time` 是传给 DS1302 驱动的 BCD 默认时间：2026-09-05，星期六，12:00:00。驱动通常只在 RTC 掉电或内容无效时使用它，并非每次开机都强制改时钟。

初始化顺序：电子秤 EXT、按键、DS1302、UART2；设置 `AA 55` 帧头匹配和 26 字节接收；注册 10 ms 与 UART 接收回调；初始化业务状态；最后启动 BSP 系统。

无限循环每轮依次：

```text
MySTC_OS
  → 处理 10 ms 事件
  → 处理接收命令
  → 尝试发送参数
  → 尝试发送状态
  → 尝试发送 RTC
```

参数帧优先于状态帧，状态帧优先于 RTC 帧。由于每次发送前检查 UART 空闲，忙时任务不会阻塞，而是保留 pending 标志留到后续循环。

## 八、`STARTUP.A51`：8051 复位启动文件

它不是业务逻辑，而是 CPU 复位后先运行的汇编代码。

### 当前配置项

| 名称 | 值 | 含义 |
|---|---:|---|
| `IDATALEN` | `0x80` | 启动时清零内部间接数据 RAM 的 0x00～0x7F |
| `XDATASTART` | 0 | 若启用 XDATA 清零，从地址 0 开始 |
| `XDATALEN` | 0 | 当前不在启动汇编中批量清零 XDATA |
| `PDATASTART/PDATALEN` | 0 | 不初始化分页外部数据区 |
| `IBPSTACK/XBPSTACK/PBPSTACK` | 0 | 未启用三种可重入函数专用软件栈 |
| `PPAGEENABLE` | 0 | 未启用 compact 模型分页初始化 |

### 复位执行顺序

1. 地址 `0x0000` 处执行 `LJMP STARTUP1`。
2. `IDATALOOP` 用累加器 A 的 0 清内部 RAM。
3. 因 `XDATALEN=0`、`PDATALEN=0`，对应清零循环不编译执行。
4. 因三个可重入栈开关均为 0，不设置专用栈指针。
5. `MOV SP,#?STACK-1` 设置普通硬件栈。
6. `LJMP ?C_START` 进入 Keil C 运行库，由运行库处理 C 初始化并最终调用 `main()`。

工程中的重要 `xdata` 业务变量在 `app_init()`、`weight_init()` 等函数中显式赋初值，因此没有依赖 `STARTUP.A51` 把整片 XDATA 清零。

## 十、一次完整业务运行示例

空载上电后，EXT 提供原始值；`app_init()` 把它作为零点并读取保存地区。每 20 ms 推入一个重量样本。放上包裹后，净重为正但窗口尚未稳定，状态为 WEIGHING、费用为 0。约 240 ms 持续平稳后 `stable=1`，状态转为 BILLING，计费模块按当前地区计算整数分。每 500 ms 状态帧把重量、费用、标志、错误和皮重发给 DWIN。

用户在屏幕点击“去皮”时，DWIN 发送带新序号的 `0x11` 帧。BSP 收齐 26 字节后置接收事件；主循环检查帧头、长度、目的地址和 CRC，再检查源地址，执行 `weight_tare()`，缓存命令与结果，回复同序号 ACK。若 DWIN 因超时重发相同命令和序号，STC 只重发缓存结果，不会再次累加皮重。

这条链路把驱动层、协议层、业务层和显示层分开：BSP 负责硬件搬运，`parcel_protocol` 负责字节格式，`weight_service` 与 `billing` 负责算法，`main.c` 负责调度和把它们组合起来。
